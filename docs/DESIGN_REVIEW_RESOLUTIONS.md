# Design review resolutions

**Date:** 14 Oct 2026
**Scope:** Review of `docs/DESIGN.md` before any application code. The trading application was not started.

Companion documents from this review:

- `docs/FORECASTING_AND_BACKTEST_SPEC.md`
- `docs/OPTIONS_EXPECTED_VALUE_SPEC.md`
- `docs/RISK_AND_EXECUTION_SPEC.md`
- `docs/DATA_SOURCE_MATRIX.md`
- `docs/IMPLEMENTATION_PLAN.md`
- `docs/OPEN_QUESTIONS.md`

| ID | Issue | Resolution | Where | Still open |
|---|---|---|---|---|
| R1 | Range thresholds 0.05% to 0.40% were written as defaults, which reads as if they were chosen. | They are withdrawn as approved values. `T` is selected on training and validation folds only, then frozen before the untouched test. | FORECASTING spec section 2.3. DESIGN decision 10. | The grid and the selection metric are research settings. No data has been run. |
| R2 | Fusion used configured numeric weights and a 0.25 disagreement cutoff as the live rule. Index trend could be mapped to a probability. | Live and paper probabilities come from the quantitative model until a fusion artifact beats that baseline under the promotion rules. LLM agreement is not an input. Hand-set weights cannot authorize a trade. | FORECASTING spec section 7. DESIGN decision 11 and section 9. | Whether any fusion feature helps is an empirical question. |
| R3 | Contract rank was a weighted sum of spread, greeks, and expected P&L. | Rank key is modelled expected net versus `NO TRADE`. Eligibility limits are constraints, not weights. | OPTIONS spec sections 5 and 6. DESIGN section 11. | Expected net is unavailable until quote, charges, and a pricing method are all present. |
| R4 | Option P&L was "stressed" without a formula. | Vendor-greek Taylor approximation and Black-76 are specified, with the conditions that disable each. IV shocks are sensitivities, not extra probabilities. | OPTIONS spec sections 3 and 4. | Theta time unit, IV scale check, European exercise flag, and futures versus spot. |
| R5 | Chain LTP could be mistaken for a tradable premium. | Bid and ask are mandatory. Groww's documented chain payload has no bid or ask. | OPTIONS spec section 2. DATA_SOURCE_MATRIX. | F&O `get_quote` has not been called. |
| R6 | Lot size, tick size, and expiry could drift into constants. | They come from the pinned instrument-master row. Tick unit is unverified because the sample CSV disagrees with a rupee tick. | OPTIONS spec. RISK spec gate 5. OPEN_QUESTIONS. | Authenticated instrument read. |
| R7 | Historical option research was implied by the backtest page. | Historical chains and expired contracts are `UNSUPPORTED` until a source is verified. No option backtest is claimed. | DATA_SOURCE_MATRIX. FORECASTING spec section 5. | A licensed history source, if one is chosen. |
| R8 | Sizing used premium and charges, but daily loss, reservations, and two workers were incomplete. | Formulas for premium-at-risk sizing, unrealized-inclusive daily loss, pending-order reserves, and `SELECT FOR UPDATE` on one ledger. | RISK spec sections 2 and 3. | Charge numbers come from the broker call, not from a statutory table in this repo. |
| R9 | A stop could be read as a maximum loss. | Long-option sizing uses full premium plus charges. Stops are exit plans. Gaps and missed exits are listed failure cases. | RISK spec sections 2 and 4. DESIGN operating rules. | None in the design. The control still does not guarantee a fill. |
| R10 | Order idempotency assumed a UUID. | Groww's documented reference id is 8–20 characters with at most two hyphens. The design uses that shape and `get_order_status_by_reference`. | RISK spec section 5. | F&O behaviour of that lookup is untested. |
| R11 | Groww capabilities were deferred entirely, including fields the public docs already name. | Matrix marks `DOCUMENTED_UNTESTED`, `UNVERIFIED`, or `UNSUPPORTED`. No endpoint was invented. F&O product code was not on the pages read, so live option orders stay blocked on that gap. | DATA_SOURCE_MATRIX. DESIGN section 14. | Authenticated read-only verification. Compliance review. |
| R12 | Quant forecast, fusion, and outcome were described as "not agents", while the required roster names them as agents. | They stay on the roster as deterministic services. Cursor is used only for the reasoning roles. None of those roles emit calibrated probabilities. | DESIGN section 5.2. | None. |
| R13 | Contrarian text could be mistaken for a veto. | Contrarian cannot change probabilities or risk results. | FORECASTING spec section 7.4. | The confirmation rule's parameters are research gates. |
| R14 | Model approval was a single `approved_at`. | States were `EXPERIMENTAL`, `VALIDATED`, `APPROVED_FOR_PAPER`, `APPROVED_FOR_LIVE`. Drift removes the model gate. An LLM cannot promote. R21 replaces the first two names. | FORECASTING spec section 6. | Gate margins are operator research settings, not proven cutoffs. |
| R15 | News sources were configurable, but URL fetch had no network guard. | SSRF checks before any configured HTTP fetch. | DESIGN section 19. | None in the design. |
| R16 | UI had ten pages and a thin dashboard. | Audit Log is a page. Dashboard must show the trade decision, premium, modelled expected net, funds, remaining budget, and the opposing case. Paper and live stay visually distinct. | DESIGN section 17. | None. |
| R17 | Scheduler did not say what happens to exits, drift, or holidays beyond a cadence. | Separate loops, fail-closed on stale data, no duplicate submit, holiday calendar. | DESIGN section 18. IMPLEMENTATION_PLAN. | The holiday feed itself is an unverified source. |
| R18 | Prompt Studio had promotion but not rollback, and injection tests were only a milestone line. | Version, evaluate, explicit promote, rollback. In-flight runs keep their hash. Adversarial cases are in the test matrix. | DESIGN section 15. IMPLEMENTATION_PLAN test matrix. | None. |
| R19 | Acceptance tests did not cover fusion losing to the baseline, SSRF, or incomplete proposals. | Test matrix in IMPLEMENTATION_PLAN. Thresholds used as pass bars are labelled research gates. | IMPLEMENTATION_PLAN. | Empirical bars do not exist yet. |
| R20 | The design could be read as implementation-ready for live trading. | Paper-on-fixtures can be built from these docs. Live trading is blocked by the open questions. This review does not call the live system implementation-ready. | OPEN_QUESTIONS. DESIGN status. | All of OPEN_QUESTIONS. |
| R21 | The orchestrator was only a Python fan-out of Cursor agents, with no graph checkpoint or resume rule. | LangGraph `StateGraph` orchestrates the V6 evidence nodes. Cursor local agents remain the LLM inside those nodes. The graph is not the forecaster, the options pricer, or the risk engine. Versions `langgraph` 1.2.15 and `langgraph-checkpoint-postgres` 3.1.3 were read from PyPI on 14 Oct 2026 and were not installed. | `docs/LANGGRAPH_ORCHESTRATION_SPEC.md`. DESIGN decision 1 and 16. | Checkpoint retention. No graph has been run. |
| R22 | Research selection could have been read as paper activation, and `EXPERIMENTAL` / `VALIDATED` did not name a research-only approval. | Lifecycle is `REGISTERED`, `TRAINED`, `EVALUATED`, `APPROVED_FOR_RESEARCH`, `APPROVED_FOR_PAPER`, `APPROVED_FOR_LIVE`, `DEPRECATED`, `DISABLED`. Approval is scoped to underlying, horizon, version, feature schema, and strategy revision. Runs pin the version at start. | `docs/MODEL_REGISTRY_AND_STUDIO_SPEC.md`. | No model is registered. No edge has been measured. |
| R23 | The UI had a backtest page but not a registry-backed studio, and candidate families could be mistaken for implemented models. | The studio lists only registry rows and shows `NOT_IMPLEMENTED`, `UNKNOWN`, `NOT_EVALUATED`, or `NOT_AVAILABLE`. Families such as LightGBM, TCN, TimesFM, and Chronos-2 are candidates. | MODEL_REGISTRY spec sections 1 and 2. DESIGN section 17. | Which optional family, if any, is later justified. |
| R24 | Finishing the paper milestones could be read as permission to trade live. | M12 is broker read-only verification. M13 is a readiness review with orders disabled. M14 is the only live-order milestone, and completing M13 does not authorize it. | `docs/IMPLEMENTATION_PLAN.md`. | API and compliance questions. |
| R25 | The design header said no application code existed. | The M0 shell is in the repository. Models, LangGraph, options valuation, and live orders are not. | DESIGN status. | M0 does not satisfy later gates. |
